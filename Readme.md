# **PDF-to-DOCX Studio: High-Fidelity Document Processing & Compiler**

**PDF-to-DOCX Studio** is a cross-platform, local web application and command-line tool designed for high-fidelity document conversion and code-based document generation. It addresses layout distortion, text box clipping, and broken formatting common in standard PDF converters through a dual-engine architecture: native vector extraction for digital PDFs and an Overleaf-style live Markdown/LaTeX code compiler for creating formatted .docx files.

## **Features**

> * **Direct Vector Layout Parsing**: Parses native text layers, margins, typography, and table structures directly into clean Microsoft Word elements without cluttering outputs with floating text frames or line-wrapped OCR artifacts.  
> * **Overleaf-Style Live Editing**: Interactive browser editor supporting Pandoc Markdown and LaTeX formulas (![][image1]) with a split-screen layout and live .docx compilation.  
> * **Google Docs Compatibility**: Produces standardized OpenXML .docx files pre-configured for seamless import and collaborative editing in Google Docs without breaking math equations or margins.  
> * **Dual Interface**: Full FastAPI web application powered by Monaco Editor alongside a lightweight Command Line Interface (CLI).  
> * **Cross-Platform Support**: Tested natively on Arch Linux, Ubuntu, macOS, and Windows 10/11.

## **Architecture**

| Component | Role |
| :---- | :---- |
| app.py | FastAPI application server, endpoints, Jinja2 page rendering, and file download management. |
| cli.py | Click-based terminal entry point for headless document conversion and compilation. |
| core/converter.py | PyMuPDF and pdf2docx vector parsing engine for extracting layout structures to .docx. |
| core/compiler.py | Pandoc and python-docx compiler transforming Markdown and LaTeX math blocks into .docx. |
| templates/ & static/ | Frontend HTML templates, Monaco Editor integration, and CSS styling for split-screen live editing. |
| tests/ | Automated unit test suite validating PDF parsing and compilation pipelines. |

The application operates as two separate pipelines: direct vector extraction (PDF ![][image2] DOCX) and markup compilation (Markdown/LaTeX ![][image2] Pandoc AST ![][image2] DOCX).

## **Requirements**

> * **Python**: Python 3.11 or newer is required.  
> * **System Binaries**: [Pandoc](https://pandoc.org/) is required for markup compilation. Tesseract OCR is optional for scanned documents.

### **System Package Installation**

> * **Arch Linux**:  
>   sudo pacman \-Syu \--needed pandoc tesseract tesseract-data-eng

> * **Ubuntu / Debian**:  
>   sudo apt update && sudo apt install \-y pandoc tesseract-ocr

> * **macOS (Homebrew)**:  
>   brew install pandoc tesseract

> * **Windows (Winget)**:  
>   winget install JohnMacFarlane.Pandoc

### **Python Package Dependencies**

Install core dependencies using pip:  
pip install fastapi uvicorn jinja2 python-multipart pdf2docx pymupdf python-docx click pydantic

## **Running the Application**

### **Option 1: Web Application Interface**

From the repository root directory, start the FastAPI application server:  
uvicorn app:app \--reload \--host 127.0.0.1 \--port 8000

*(Alternatively, execute python app.py if configured).*  
Access the application in your browser:

> * **Web UI Editor**: http://127.0.0.1:8000  
> * **Interactive OpenAPI Documentation**: http://127.0.0.1:8000/docs

### **Option 2: Command Line Interface (CLI)**

Run document conversions directly from your terminal:

> * **Convert Native PDF to DOCX**:  
>   python cli.py convert path/to/document.pdf \-o output.docx

> * **Compile Markdown/LaTeX Code to DOCX**:  
>   python cli.py compile path/to/document.md \-o compiled.docx

> * **View Available Options**:  
>   python cli.py \--help

## **How to Use**

### **1\. Direct PDF-to-DOCX Conversion**

> 1. Open the Web UI at http://127.0.0.1:8000 and select the **PDF Converter** tab.  
> 2. Upload a native digital PDF document.  
> 3. Click **Convert & Download**. The engine extracts native text vectors, structural tables, and fonts into an editable .docx file.

### **2\. Overleaf-Style Code Compiler**

> 1. Select the **Code Editor** tab in the Web UI.  
> 2. Write or paste structured document content using Pandoc Markdown and LaTeX math syntax (e.g., inline math $a^2 \+ b^2 \= c^2$ or block math $$\\int\_{0}^{\\infty} x^2 dx$$).  
> 3. Click **Compile DOCX** to trigger the Pandoc compilation pipeline and download your styled Word document.

## **Google Docs Integration**

To import files generated by PDF-to-DOCX Studio into Google Docs without breaking equation syntax or margins:

> 1. Upload the generated .docx file to **Google Drive**.  
> 2. Double-click the file and select **Open with Google Docs**.  
> 3. Choose **File \> Save as Google Docs** to enable live collaborative editing with native document formatting intact.

## **Expected File Formats**

> * **PDF Conversion**: Vector-based (digital) PDFs yield optimal formatting preservation. Scanned image PDFs will fall back to OCR layout approximations where configured.  
> * **Code Compilation**: Accepts standard Pandoc Markdown (.md, .txt) with inline and block LaTeX math blocks. Custom styles can be applied via reference template files (reference.docx).

## **Output Artifacts**

> * Processed .docx files are generated in-memory or saved directly to specified output destinations via the CLI.  
> * Temporary files uploaded during web sessions are stored in designated temporary directories and cleaned up post-processing.

## **Limitations**

> * Native PDF conversion relies on structural vector text layers; scanned raster image PDFs without text layers require OCR and may experience minor layout variance.  
> * Extremely complex multi-layered vector CAD diagrams inside PDFs may be flattened into raster visual elements during extraction.
